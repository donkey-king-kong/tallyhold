## Architecture and source of truth

Place an independently packaged TypeScript VS Code extension in `extensions/agent-monitor/`, with its own `package.json`, lockfile, `tsconfig.json`, build/test configuration and VSIX allowlist. Contribute `Tallyhold Agent Monitor: Open` and a webview panel. Target the stable VS Code extension API with proposed `engines.vscode: ^1.80.0`; do not use proposed APIs. This is a **candidate API floor**, not a claim that a particular Trae release supports it: record installed editor versions and test the actual VSIX in both before calling either compatible. Do not add the extension to frontend dependencies.

| Boundary / planned files | Responsibility |
| --- | --- |
| `src/extension.ts`, `src/host/monitorPanel.ts` | Activation, panel lifecycle, worktree stream discovery, file picker, host-owned source switching and disposal. UI messages are a small validated union (`selectSource`, `selectNode`, `setFilter`, `fitAll`); no webview command/file URI execution. |
| `src/host/sourceReader.ts`, `src/host/metadata.ts` | Local `file:` JSONL reader, watched/polled reconciliation, byte offsets and generation resets; optional same-directory `session.json`/`heartbeats/` as advisory metadata. The extension host owns all filesystem access. |
| `src/core/{parse,reconcile,reduce,graph}.ts` | Framework-free parser and deterministic projection of the publisher's records; source identity, execution intervals, diagnostics, relationships and immutable graph positions. No VS Code imports, so replay can be tested in isolation. |
| `src/shared/protocol.ts` | Bounded, typed host/webview messages and runtime validation at both ends. Cross the boundary with plain data only, never raw commands or trusted HTML. |
| `src/webview/{main,graph,inspector,styles}.ts` and `media/` | Editor-themed SVG graph with persistent layout and camera, inspector and keyboard-accessible node navigator; locally bundled assets only. |
| `test/{core,host,webview,editor}/`, `fixtures/` | Synthetic records only. Parser/reducer/property scenarios, mocked reader recovery, DOM interaction/accessibility tests and packaged-editor smoke harness. No copied `.agent-flow/` logs. |
| `README.md`, `docs/verification.md`, `.vscodeignore` | Install/select/recover instructions, supported/untested versions and measured limits; inspect the actual VSIX allowlist. |

No separate ADR or design-system file is proposed: the extension boundary and trade-offs are recorded here for Zack's gate. If an approved implementation needs a significant deviation, return to Zack rather than silently changing the contract.

### Stream identity and replay

Use an immutable **selection key** (canonical local path plus a host selection generation), a **file generation** (stat identity, length, modification metadata and content continuity checks) and a **session key** (`sessionId` in each valid record). Never key an agent by name alone: node key is selection/file generation + session ID + published agent ID. A switch creates a fresh projection and camera, cancels stale asynchronous reads by generation token and never merges results from the previous selection. Reopening a panel reconstructs from source bytes, not serialized webview state; persist only the selected URI when appropriate, never event history. A workspace shortcut discovers that worktree's `.agent-flow/agent-flow-events.jsonl`; explicit local file selection is also supported. Show full selected path, session identity or `unavailable`, and reader state separately.

The host reads raw bytes. A stateful UTF-8 decoder handles a partial multibyte character and retains a partial line until LF; commit a record only after its newline. Complete malformed JSON, invalid schema or unsupported `type` emits a line/offset diagnostic and processing continues. Check finite nonnegative relative `time`, object `payload`, string `sessionId`, and per-event identity fields; preserve unrecognized payloads as inert diagnostics, not executable data. File byte offset is the ingestion identity: replaying a notification or identical existing bytes has no effect; two equal-valued lines at different offsets are separate records. Tests must feed the **same byte sequences** in one batch and split at every byte boundary, including inside UTF-8.

Serialize file reads per source. On each notification (plus a modest fallback reconciliation timer while the panel is open), compare stat and continuity evidence before appending. Inode/device changes, shrinkage, same-size rewrite, changed metadata with a prefix/content mismatch, or an incomplete append after a reset start a **new generation** and replay current bytes from zero. A digest of the accepted prefix on a changed file checks append continuity; unchanged notifications need no reread. Treat a source whose identity cannot be established as a full replay, not as an append. Watchers are hints, not ordering authority. On temporary read failure, keep the last valid projection, label it stale with the error and last successful read time; retry without fabricating events. On recovery reconstruct or continue only after continuity checks, and never write to the log. A missing initial file has an actionable empty/error state, not a green connection.

One selected file has one expected session ID from its first valid record; a mismatched record produces a diagnostic and is excluded from that projection. If the file is replaced, the new generation may have a new session. Events are reduced in **source order** (the only authoritative append order), with reported relative time displayed as given; out-of-order time is flagged, not sorted into invented chronology. Snapshot `session.json` may translate relative time to an absolute date only when its ID matches, start is valid, and derived chronology is consistent. Without that anchor, show the event's session-relative timestamp, not an absolute date or fabricated wall-clock age. Optional heartbeat files have no session ID and whole-second `updated_at`: display only as explicitly attributed, provisional companion observations for the same canonical worktree directory; never overwrite event state, interval boundaries or confirmed history with them. For an arbitrary selected file, companion reads require an exact sibling session match; missing/malformed/stale metadata produces a diagnostic but cannot hide valid JSONL.

### Projection and relationships

`agent_spawn` starts an execution interval for that source/session/ID; if the ID exists, retain its node and previous intervals and mark the new interval. `agent_complete` closes an open interval with its reported terminal status. A completion without a matching spawn, repeated completion, post-terminal activity without a new spawn, or truncated start/end is represented as **incomplete/ambiguous**, not repaired with invented times. Dispatch and return are reported activities; they do not prove an independent process, spawn, or unobserved work. Status comes from the latest applicable explicit report (`message`, `permission_requested`, `error` with its reported status, completion), not elapsed wall time. An isolated `tool_call_end` reports its outcome; a failed tool is not an agent failure. Tool start/end can only be associated as a tentative pair when exactly one candidate in that agent/category is open; multiple simultaneous candidates remain unmatched/ambiguous. Tool counts use distinct source records, never guessed pair counts.

Track missing parents on real child nodes with an unresolved-parent annotation; do not invent a parent agent. Resolve a late-arriving parent edge without moving either node. Detect self-links and cycles before accepting a graph edge; keep every real node reachable in the root/unresolved group with a diagnostic. Allocate immutable positions at first sight: fixed depth columns for known acyclic parents and deterministic unoccupied row slots nearest the parent's row, with a root lane for orphans and late edges. New nodes occupy new slots; status, filters, delayed relationships and append never repack existing nodes. Edge routing can change when a valid parent appears, but node coordinates cannot. The selected stream owns its camera; updates and active-only filtering preserve its pan/zoom. Initial open and explicit Fit All compute bounds over **all** nodes, including terminal and unresolved nodes; pan/zoom and a keyboard node navigator reach nodes outside the viewport.

The default shows every reported node. Active-only is explicitly labelled **"Last reported nonterminal"** with an explanation that it does not establish process liveness. A clock updates "last report" wall age while idle only with a verified session-start anchor; otherwise a newly observed event can show separately labelled **"observed locally X ago"** from its monotonic receipt time, while an old historical event's wall age is `unavailable`. Reader state (`reading`, `following`, `stale`, `error`) and agent state (`reported working`, `reported completed`, `unknown`, etc.) have distinct labels and visual roles. Counts state what they count (reported identities, activity records, diagnostics), not tokens, inferred work or actual live processes.

### IDE interaction and privacy

Impeccable **Operate** direction: an editor-native inspection tool, not an animation or portfolio dashboard. The header names the selected worktree/path, session and reader health; the graph remains the main spatial overview; a resizable inspector gives identity, task, last reported status, last-update age and chronological records with source-relative times and clear success/failure/ambiguity labels. A compact node navigator offers a linear, searchable alternative to spatial exploration. On narrow panels, details stack beneath the graph without covering Fit All or trapping keyboard focus. Empty, unreadable, stale, malformed, mismatch, large-log and recovered states use concise action-oriented copy; the last valid graph remains visible beneath a stale banner. No automatic playback, fading of terminal nodes or distracting motion. Respect `prefers-reduced-motion`.

Use editor theme variables and VS Code high-contrast tokens, semantic text labels plus non-color marks for status, visible focus, sufficient contrast, and accessible names for every node/control. Keyboard users can select a node and inspect its history through the navigator, toggle the filter, pan/zoom via controls and trigger Fit All. Preserve focus and selected identity through updates/filter toggles; if the selection is filtered out, explicitly explain it and provide a reveal action. Test light/dark/high-contrast and narrow/wide panel layouts. Never claim a role alias is a distinct process; show published names as **reported identity** and uncertain identity kind as `unspecified`.

The host only opens the chosen local JSONL and relevant companions. In untrusted workspaces, do not auto-discover/read a workspace source; an explicit file selection remains a user action with a visible path. Restrict webview `localResourceRoots` to bundled media, use a nonce-based CSP with `default-src 'none'`, no remote script/image/connect source, and render all telemetry as text nodes, never HTML, markdown URLs or command links. Validate and bound inbound messages, ignore stale generation messages, and do not issue network requests or mutate publisher files. Package an explicit allowlist and inspect the VSIX for ignored runtime logs, credentials and development fixtures. No new automatic hooks or agent-control operations.

## Resource envelope and dependencies

Propose first-release support for a selected file up to **64 MiB, 100,000 complete records, 2,000 identities and 1 MiB per line**. These are explicit acceptance-bound engineering limits, not silent eviction: if crossed, keep the last valid view, mark it incomplete with the breached limit and recovery guidance, and do not label it a fully connected stream. Ask Zack to approve these limits; if they exclude required real workloads, revise the design before RED. Bound decoder buffers, diagnostic display and DOM rendering; keep full accepted history available through a virtualized/paged inspector and viewport-cull graph rendering without dropping source records. Release watcher/timer/reader resources on switch or panel disposal.

Target a representative synthetic **10 MiB / 20,000-record / 500-identity** file: cold reconstruction <=3 seconds, 200 appended records visible <=250 ms after a notification, and local selection/Fit All response <=100 ms on the recorded development machine. Also measure the 64 MiB envelope and memory, recording observed hardware/editor versions; these are proposed targets, not asserted measurements. Do not mask slow paths with animation. Use TypeScript, bundled DOM/SVG and the VS Code API with no runtime graph/layout dependency; build with `esbuild`, typecheck with `tsc`, lint with ESLint, test with Vitest and V8 coverage, package with `@vscode/vsce`, and run integration smoke using `@vscode/test-electron` for VS Code plus manual/automatable Trae VSIX installation on the actual installed version. Pin dependencies in the extension lockfile and audit them. If the proposed API floor, timings or dependency/tooling cannot be proven in both editors, report the gap before release.
